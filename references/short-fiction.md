# 中文短篇小说去 AI 规范

适用于约 8k–3w 字的中文短篇小说正文、章节片段、短篇大纲和续写，覆盖情感、悬疑、世情、重生、系统、游戏等类型。目标不是把文本洗成“标准文学腔”，而是保住故事核、爽点、反转和人物关系，把模型常见的整齐、抽象、解释过量和自造因果压回具体叙事。

本文的硬线是诊断条件，不是逐词禁令。用户明确指定的叙述声线、地域口语、古风、诗性或情色语域属于 protected span；只处理模板腔、替代场面的漂亮话和不成立的因果。只有完整稿才能评估全文比例；若输入只是片段，明确写“无法评估全篇项”，只处理可见内容。“节”按用户已有章节划分；没有章节标记时，按自然场景或时间切换估算，不凭空补数字。

## 1. 先分清要修什么

短篇常见的三种问题不能混为一谈：

- **结构问题**：主线漂移、冲突无结果、反转没有铺垫、结尾提前总结。需要重排或删减，单纯换词无效。
- **表达问题**：自造词、自造因果、翻译腔、系统说明书、句子过匀、人物说话不像本人。适合局部改写。
- **材料不足**：删掉姿态层后缺少能承载篇幅的事件、代价或感官细节。交付时列出缺场面位置，保留原文事实，不用新比喻填空。

默认顺序：保故事事实和人物选择 → 修因果和结构 → 修场面和节奏 → 修人物语域 → 修词句。不要倒过来先扫词表。

## 2. 剧情账本

动笔前用几行内部记录（不必展示给用户）：

- 主角此刻在哪里，缺什么，想得到什么；
- 本节主角做了什么选择，承担了什么代价，结果改变了什么；
- 每个设定的规则、触发条件、限制和已兑现用途；
- 反转的核心事实、至少三条可回看的隐线和一条误导；
- 配角各自的目的、能力边界、进场理由和离场结果。

改写后逐项回读。不得凭空新增能力、资源、亲密关系、敌我立场或情节结果；不得把“可能、似乎、想要”改成“已经、必然”；不得把抽象对象改成原文没有的具体产品、职业或机制。

新设定第一次出现时，尽量在三句话内落地：它是什么、为什么此刻重要、对人物意味着什么。若答案必须延后，先给异常和限制，不要用百科式说明抢先解释。

## 3. 短篇结构硬线

### 开头

前三句内同时出现人物处境和冲突/反常。可以写天气、温度、末世年份或制度背景，只要它们本身制造危险、限制或选择；禁止的是与人物无关的背景清单、世界很乱的空泛概括、主角泛泛震惊或作者介绍。

坏例：`我第一次把道路工具拖出来时，荒原静得发冷。别人在废土里先找枪，我先找路。`

问题：抽象、通用、没有当下阻力，也没有说明“为什么现在必须这样做”。

可用方向：把“修路”与正在逼近的缺水、伤员、追兵、断电或路线选择绑定，让道路成为动作而不是口号。

### 单线和冲突

- 一篇围绕一个核心反转或核心难题，支线只服务主线；
- 每次争吵、战斗、交易或系统操作必须带来获得、失去、暴露、升级、改变或代价；
- 结果应在约 2–3 节内兑现，不能用无结果争吵和重复赶路拖篇幅；
- 每 2–3 节至少有一次态度反转、新信息、打脸或章末卡点；钩子必须改变局面，不能只是换一种说法宣布“更危险了”；
- 主角在行动节至少做一次选择。纯收束、后果展示或群像承接节可以例外，但不能整篇都只等系统或反派推动；
- 设定一旦出现，就要在故事中使用并遵守，尤其是资源、温度、能源、权限、距离和能力限制。

群像或大场面不要写成逐人点名清单；至少让一个具体人物受伤、掉队、失去物资、暴露立场或做出关键动作，让场面产生可追踪的代价。高潮尽量安排一次“豁出去”的选择；若作品刻意走低烈度路线，则明确写出人物承担的关系、名誉或现实代价。

信息释放优先遵循：先出现异常 → 人物产生猜测 → 用行动或证据验证 → 付出代价 → 只拿到部分答案。非反转型作品可把这条换成“情绪升级 → 选择 → 后果 → 情绪落点”。

### 反转和结尾

- 对反转驱动的作品，核心揭示通常放在全文 60%–85%，并准备至少三条隐蔽线索和一条误导；非反转型作品不强行制造谜底，改查核心难题、情绪闭环和前文回收；
- 反转揭示尽量控制在 300 字以内，用证物、动作、场景变化让读者自己拼出来，少用角色长篇解释；
- 高潮最好有一次明确的冒险或代价。单靠“主角早已算好”或系统临时发奖励，会让胜利失重；
- 高潮或反转后约 500–1000 字收束；
- 结尾定格在一个动作、物件、画面或人物台词。金句只有在场面已经成立时才有效，禁止用作者总结替代结尾。

## 4. 重点清理的 AI 模式

### 4.1 空泛升华和宣传稿收尾

识别：`那一刻我知道……`、`给这片死地重新起名`、`文明重新点燃`、`命运的齿轮`、`这一刻，新的时代开始了`。

处理：回到同一场景里的下一步动作、可见变化或人物反应。比如“路灯亮了”后写主角把图纸往前推、去接第二段路，而不是宣布城市获得新生。

### 4.2 硬拗因果和拟人化召唤

识别：`她是电力节点自己长出来的人`、`她不是来投奔的，是被城里的电叫来的`、`由地热抽水泵过滤出来的热咖啡`（仅当作品设定未授权这种拟人化或跨功能因果时）。

问题：主体、动作和因果不符合人物常识或设定物理属性；把“从哪里来、为什么来、谁做了什么”压成一句自造句。

处理顺序：写她从哪里赶来 → 她看见了什么故障 → 她做了什么判断 → 她提出什么条件。设施提供热量可以写暖水、供暖或冲咖啡的电力，不能让抽水泵承担过滤咖啡的动作。

### 4.3 系统/游戏说明书

识别：连续弹出系统提示，罗列解锁项、属性、任务和奖励；角色开口解释机制；一段话里出现“居民、商业、工业三条需求条一起亮了”等界面清单。

处理：保留会直接影响当前选择的面板数值、道路规则、资金扣除和系统事实，其余才转成主角的感知和操作。每次机制出现都要落到：规则是什么 → 主角怎么操作 → 环境/敌人如何受影响 → 有什么限制或代价 → 结果是什么。系统提示可少量作为界面质感，但不能代替场面；允许信息延迟兑现，不要求每次都立即解释完整。若作品已经建立“系统行一条条排队显示”的格式，按原顺序保留关键提示，不要把整组提示改成旁白；只清理同一事实的重复提示，提示后的叙述必须提供新的动作、反馈或代价。真实的直播间碎片也不能因为带括号就一律删除，用户明确要留的损人弹幕（如“【下一位，别浪费直播间流量。】”）按 protected span 处理。

对于游戏改编或系统文，游戏联动要靠可验证的操作链（道路、区划、供水供电、寻路、噪音、垃圾、推土机等）推动剧情；不要只贴游戏名、工具栏名和数值标签。
现实题材、情感题材或无系统文本跳过本节，不强行套用这些例子。

### 4.4 电报体、断词和不完整说话

识别：`眼睛底下全是青。几夜没合眼。这袋米拿走。她撑不过这个月。`、对白只剩半个动词、标点单独成行、汉字被拆散。

处理：先判断短句是否承担紧张节奏。不是为了“句子完整”而把所有短句并成长句；但观察、心理和解释不能被切成词条。对白要像人物在当时能说完的话，保留口吃、停顿和打断，但不能像生成失败。

### 4.4.1 不完整动宾句与悬空动词

“拖、耗、欠、逼、管、接、靠、等、陪、救”这类动词，若需要说明对象、方式、范围或后果，不能单独写成“我不拖你”“我不欠你”“我不逼你”“这事我不管”“这单我接”。有一个代词不等于信息完整：`拖你`仍可能没说清拖什么、拖多久或会耽误什么，`欠你`也可能没说清欠的是钱、情分还是哪一笔账。

改写时先补对象或结果，再考虑口语化：

- `我不拖你` → `我不再占着你的时间，十分钟内给你回话。`
- `我不欠你` → `油钱今晚转给你，这趟不记账。`
- `我不逼你` → `你不想签就先放着，明早再决定。`
- `这事我不管` → `你自己定，我不替你担这份责任。`

补不清时，直接写动作和后果：`他把单子推回去，没替她签字。`上下文已经交代清楚对象、方式和结果时，可以保留自然省略；“靠！”等感叹词，以及“靠着墙”“靠这笔钱过冬”等对象明确的用法，不按本条处理。禁止用另一串抽象承诺或同义词轮换掩盖成分缺失。

### 4.5 过度抛光和节奏过匀

识别：每句长度相近、每段都有漂亮收束；连续使用“缓缓、渐渐、顿时、终于、仿佛、似乎、心头一震、呼吸一滞、眼神复杂”；同一种二元句式反复出现。

处理：保留最贴切的一处，其余改成动作、声音、物件或直接判断。不要为了躲重复而强行轮换同义词；关键词在叙事中正常重复。适当留下自然停顿、粗糙和未说满的话。

短篇里尤其检查成串出现的 `一半……一半……`、`没有……没有……`、破折号和省略号。它们不是绝对禁用，但连续出现会制造“对仗答案感”；优先改成普通连接、句号或人物真正的停顿。
**强制禁用一种固定骨架**：`条件触发 + 资源/结果对照 + 先缺（或先出）结论`，如“那地方一旦被打穿，城里不缺枪，先缺水”。它不是普通条件句，而是把条件、比较和结论排成三拍口号。`一旦/如果/真要……，不缺 A，先缺 B`、`一打穿就……，A 有的是，B 先断`等同义变体也不允许出现在生成或改写的小说正文中。应拆成供给变化、人物反应或实际选择；不要只把“先缺”换成“最先没有”来规避。引用原文可保留，技术说明则按其自身语域判断。
半文半白、算命腔、玄乎修辞只有在用户指定或人物语域需要时保留，否则压回当代可理解的表达。

### 4.6 死板机械的职能宣言与伪格言对白

短篇对白强制过滤以下组合：

- **职能宣言**：`我负责让该关的门关上`、`我就是来把事情做完的`。句子只宣布职责，没有正在处理的对象和动作。
- **万能对比**：`卡车没有变新，只是能跑了`、`不是为了好看，是为了能用`。如果没有具体的维修结果或人物语气，这类“没有 X，只是 Y”就是预制的解释腔。
- **物件拟人后下判断**：`账比人还难伺候`、`招牌不卖货，货架上的东西才卖钱`。物件被拉来替人物讲道理，容易变成伪金句。
- **概念接力式对白**：`我信账。` `账也是人写的，写错一笔，下面的人就得跟着吃亏。` `那就把每一笔都摊开写。` 多句都在替“账、责任、实用”下主题答案，缺少当下的停顿、误解、动作或利益冲突。

命中后不能只换几个词，也不能把整段改成另一组押节奏的金句。优先写人物手里的东西和正在做的事：谁翻开哪一页、哪项数字对不上、哪扇门没关、卡车哪里漏油、谁因此要承担损失；对白可以短，但必须像人在现场说话，允许没说完、改口、顶回去。若原文没有足够事实支撑，就删掉宣言层，不补新的漂亮话。

### 4.7 命名式总结、金句腔和作者剧透

识别：`这叫……`、`这就是……`、`懂吗`；人物说格言、对仗句和主题答案；叙述者提前告诉读者“真正的危险不是……而是……”。

处理：删除标签，给事实或行动。人物只说他此刻会说的话；主题让读者从代价和结果中得到，不替读者做阅读理解。

开篇不要把谜底、幕后身份或机制答案提前说完；系统文也不要让人物把“系统发任务、我挑对象、这是降维打击”直接念出来。让异常先出现，猜测和验证随后发生。

### 4.8 角色工具化和擦边外貌堆砌

任何角色的进场理由不能只是外貌标签、身份标签或“倒贴”。用户明确需要的外貌、情色语域和类型化装束可以保留，但不能重复替代行动；否则改用职业动作、说话方式、利益冲突、专业判断和对主角方案的态度建立吸引力。后宫线必须有选择、边界、互相竞争或合作的具体事件，不能用“好感度爆表、彻底征服、宣誓效忠”一句带过。

### 4.9 暧昧与擦边情趣场景

这类片段的目标是让读者看到两个人正在靠近，而不是让叙述者替他们宣布“很性感”。默认只写明确成年人物；年龄不明时保持普通关系描写，不进行性化处理。非露骨范围可以写衣物、湿痕、肩颈、锁骨、腰线、腿部、贴近、牵手、亲吻和双方自愿的暧昧触碰，但不写生殖器、裸露性行为或具体性行为过程。

**写法顺序**：

1. 先给一个有压力的场景（停电、狭窄房间、雨、换衣、处理伤口或共同做事），不要先解释两人的关系；
2. 只挑一两个服装细节，且必须随着动作变化（湿衬衫贴住、肩带滑落、领口被拉近、外套被拿走），不要逐项盘点胸、腰、腿和肤色；
3. 用距离、视线、手的去留、被打断和退不退开推进张力。触碰之后必须有回应、拒绝、试探或加深，不能只写“他看见，她很诱人”；
4. 对白说眼前的事，带一点试探或回避即可。禁止“你在躲我”“利息以后算”“现在还躲吗”这类可互换角色的套路挑逗连续出现，也禁止人物轮流说主题金句；
5. 试写片段删掉解释性前言和结尾总结，直接停在一个动作、一个吻或一次明确的退让。每段都要有动作或关系变化，删掉只负责说“气氛暧昧”的句子。

**自查**：删去所有“性感、魅惑、撩人、勾魂、暧昧气息”等形容后，场景是否仍能靠衣物、距离和回应成立；如果不能，说明写的是标签，不是情节。不要把“露骨”误解成堆更多身体名词，服装的暴露程度应服务于人物的主动选择和现场阻力。

### 4.10 前言不搭后语、无效对白与废话文学

以下两类句式在短篇正文和人物对白中默认强制过滤：

```
❌ 这不是荒岛求生，这是修理工加班。
❌ 别修了，修好了也没有电。
```

第一句把生存处境和职业标签硬拼成标题式对照，第二句先否定动作，再补一个没有新信息的结果。它们的问题可以分别叫作：**前言不搭后语**（两个概念不在同一关系链上）、**无效对话**（不影响信息、关系、选择或情绪）、**废话文学/反向口号**（靠否定和反转制造“有道理”的感觉）。同类变体包括：`这不是 X，这是 Y`、`别做 A，做完了也没用`、`看起来在 A，其实是在 B`，以及把作品类型、职业、主题和眼前动作强行并列的句子。

处理时先问四件事：谁在说、看见了什么、想让对方做什么、这句话说完后现场有什么变化。没有答案的句子删掉；有信息但关系写歪的，拆成事实和反应；有意说废话的，给它明确的敷衍、嘴硬、误会或打岔功能。对白可以不完整、重复和改口，但不能只靠换几个口语词继续当标题。

### 4.11 反工整与感官钉子

短篇去 AI 不等于把每句话写得更短、更利落。检查段落里是否出现“甲做一个动作，乙做一个动作，丙做一个动作，大家统一反应”的动作接龙；改成同场人物各有目标，动作互相妨碍，或有人根本没按预期反应。不要让所有人同时抬头、皱眉、后退、沉默。

可以补一两处不推动情节的普通感官细节，让场面有温度和阻力：油沾在指缝里，湿衣服贴着背，嘴里有金属味，坐久后腿麻，风从门缝钻进来。它们必须落到人物身体和物件上，不能写成抽象气氛，也不能每句都加。感官细节的作用是让人物像在现场待过，不是替空场面充字数。

### 4.12 口语、弹幕和情绪节奏

对白可以有停顿、语气词、重复、改口和抢话。修改时保留每个人的说话习惯：有人只说半句，有人爱反问，有人先骂再解释，有人习惯把话咽回去。不要把所有角色统一改成“自然、机灵、会接梗”的声音。

直播间弹幕和评论要像现场碎片，不要排队替作者讲解剧情。删掉或改写“震惊、反转、打脸、太燃了、这波稳了”一类盖章词；保留真正改变判断的评论、互相矛盾的猜测、没说完的短句和偶尔跑题的反应，但不能凭空增加新的事实。系统提示另行处理：若作品已经建立逐条排队的系统框，就保留关键提示和原有顺序；只删重复播报，不能把系统行和紧邻旁白写成同一事实的两遍说明。情绪也不要每隔几句就盖一次“震惊”或“反转”，让迟疑、嘴硬、回避、失手和关系变化承担过程，结果仍要落地。

### 4.13 文笔落点、动作链与系统队列

去 AI 不是把句子弄糙、弄短，也不是为了“像人”硬塞行业黑话。优先使用普通、准确、读者一眼能懂的词，把动作顺序写完整，让声音、视线、手上动作和对白接在同一条现场链上。比如“我正蹲在船坞边拧螺丝，突然听见发动机的声音，只见三艘快艇正在飞速驶来”虽然是一个长句，但顺序清楚、词也正常；不要改成“螺丝只咬半圈”这种自造修理术语。发现动作不连贯时，先修因果和先后，再考虑句长。

同一事实只能呈现一次。旧句和新句不能并排，系统提示和紧邻旁白不能把同一个结果播两遍；保留系统行时，旁白必须换成新的动作、反馈或代价。用户或作品格式明确要求系统提示一条条排队显示时，系统队列本身是叙事设备，不是“说明书腔”，不要把它整组删掉。真实直播间的损人、跑题和没说完的碎片也可以保留，不要因带括号就一律改成旁白。

节奏可以借鉴短段落、快对白和密集小兑现，但不能复制“动作一段、反应一段、弹幕一段”的固定循环。每段至少推进一个动作、判断、资源变化或关系摩擦；人物的爽点来自对手的选择失误、资源损失和规则兑现，少用连续羞辱、擦边或“全网震惊”盖章。章节结尾留下下一步问题，下一节再兑现，不用作者替读者宣布“反转成功”。

### 4.14 正式剧情中的注意力保护

正式冲突、判断或对白正在推进时，不要突然切去描写无关的动作、环境或感官，把读者从当前问题上带开。这不是“环境描写越少越好”，而是每个细节都要接住眼前正在发生的事，并至少改变一个可追踪的东西：人物的选择、关系、风险、资源或信息。没有作用的细节删掉；确有必要但不值得展开的，压成一句贴着动作写完。

对用户称作“压算认催”的处理保持谨慎。术语含义、人物意图或剧情后果有一项不清楚时，不要擅自把它变成动作、环境或心理段落，也不要把它当作固定节奏按钮和转场借口。去 AI 的目标是让读者更清楚地跟上剧情，不是用新细节把注意力挪走。

## 5. 系统与战斗场景的合理性（仅在文本命中时启用）

“无脑爽”不等于没有因果。爽点应来自规则稳定、对手做出符合自身利益的选择、主角抓住规则漏洞或优势。

- 怪物为何来：资源、能量、气味、领地或繁殖条件必须在设定中成立；
- 人为何斗：人口、食物、能源、税收、路线、技术或安全边界必须产生真实利益冲突；
- 主角为何能赢：明确的权限、地形、准备、规则限制或对手误判；
- 赢的代价：资源消耗、设施受损、暴露能力、失去盟友、欠下人情或留下新的威胁；
- 规则不能临场只为秒杀服务。若有强制寻路、推土机抹除、自动治安等超常机制，应提前展示边界和触发条件。

战斗不要写成“敌人冲来 → 系统判定 → 敌人消失 → 获得金币”。至少给出一个可感知的压力、一个主角的现场判断、一个具体操作和一个可追踪的后果。

群像或大场面也不要逐人点名报平安。写谁受伤、谁掉队、谁的物资被毁、谁在关键时刻做了什么；具体代价比“所有人都陷入混乱”更能让场面活起来。

## 6. 改写操作

按以下顺序执行，避免把审稿变成同义词替换：

1. 圈出保护内容：数字、设定规则、人物关系、专有名词、引用、系统事实和必要的粗口；
2. 标出病灶类型：材料不足、结构、因果、系统说明、抽象比喻、自造词、断句、语域、角色工具化；
3. 先删/并纯空句，再把剩余句子改成“谁在何处做什么，造成什么变化”；
4. 每次重大改写后做事实回读和人物动机回读；
5. 最后才做残留味复扫。发现“像、仿佛、终于”不必机械全删，要看它是否承担真实感官信息。

默认输出一版可直接使用的正文。用户只说“润色/去味”时，先保守使用 `standard + bounded`；用户明确允许整篇重构时才使用 `structural`。用户说“只标问题”时，不给整段重写，只列 1–5 个最高优先级问题，并注明是材料不足、结构问题还是表达问题。发现材料不足时附“缺场面清单”，写出位置和缺少的事件、代价或感官信息，不擅自补写。用户要求保留句数或完全原样时使用 `in-place`，不删整句、不并句、不重排。

## 7. 短篇交付自查

### 内容

- [ ] 前三句有人物处境和冲突/反常；
- [ ] 主线单一，支线都能回收；
- [ ] 每次冲突有结果和代价；
- [ ] 主角有选择，不只接收提示；
- [ ] 反转型作品有三条隐线和一条误导，揭示不靠长解释；非反转型作品的核心难题或情绪闭环已回收；
- [ ] 信息按异常、猜测、验证、代价、部分答案逐步释放，或在非悬疑型故事中完成情绪升级、选择、后果、落点；
- [ ] 每 2–3 节有改变局面的钩子，高潮有一次承担代价的选择；
- [ ] 群像场面通过具体人物的动作和代价呈现，不是点名清单；
- [ ] 结尾落在画面、物件或台词，而不是主题宣言。

片段稿无法评估全文比例、反转位置和全篇钩子密度，必须标注“无法评估”，不凭空推断。

### 语言

- [ ] 没有空泛开场、宣传稿收束、作者剧透；
- [ ] 没有“被某个抽象东西叫来”“某设施过滤出不相关物品”等硬拗因果；
- [ ] 系统信息已经转成感知、操作、环境/敌人反馈、限制和结果；
- [ ] 正式剧情推进时没有突然插入无关的动作、环境或感官描写转移注意力；每个保留的细节都改变了选择、关系、风险、资源或信息中的至少一项；
- [ ] 没有大量“这叫/这就是”、对仗金句和否定翻转；
- [ ] 没有断词、残句、碎标点或人物不会说的话；
- [ ] “拖、耗、欠、逼、管、接、靠、等、陪、救”等动词没有悬空；对象、方式、范围或后果已经说清；
- [ ] 比喻能被场景验证，不能只负责抬气氛；
- [ ] 同一类高频词没有成串出现，也没有为了躲重复而乱换词。
- [ ] 已抽查“盯着那行字、愣住、忽然、然后、这账、那口气、心没落地、看着”等口癖；命中只作上下文线索，不作自动禁用。

### 设定和人物

- [ ] 规则前后一致，设定过的东西至少兑现一次；
- [ ] 怪物和人类冲突有利益或生存依据；
- [ ] 配角有自己的目标、动作和结果；
- [ ] 主要人物的说话方式能区分，配角有来处、有去处，离场会留下结果；
- [ ] 后宫/情感线靠事件和选择推进，不靠外貌清单或好感度播报。

## 8. 句级别扭表达审校

当用户要求“逐条找别扭句”“修改对话和叙述”或给出句级问题清单时，在结构诊断之后执行本节。先按上下文判断，不按词面一刀切。

### 8.1 逻辑与关系

检查时序错置（先/再/然后与因果不符）、条件句缺少“要是/如果/只要/一旦”、因果被句号硬切、概念强行并列或混合、前后设定矛盾、反常识判断。核对动作和结果谁先发生、条件是否成立、主语是否一致；不要把有意悬念误判成矛盾。

### 8.2 词语搭配与语法

检查动宾搭配、量词、宾语缺失、补语顺序、过度省略、书面直译、翻译腔和生造术语。优先恢复“谁对什么做了什么”，把“完成了建设/开始使用”改成自然动作，但作品设定术语和专名必须保留。

### 8.3 对话与叙述衔接

检查说话人归属、对话标签、动作插入位置、人物语气与身份/情绪是否一致、对白书面化、缺宾语或指代、反问/感叹结构和逻辑跳跃。动作夹在两段对白之间时，若打断了同一口气，改为前置、后置或压成一句动作；有意打断、抢话、停顿则保留。

### 8.4 描写与场景

检查违背常识的描写、比较级搭配、把人物写成机器/数据、动作与地点或道具脱节、绕口的被动句和把字句。先核对作品世界观；奇幻拟人、非人角色或作者明确的夸张语域可以保留，问题只在设定没有支撑或读者无法理解时处理。

### 8.5 标点与节奏

检查标点是否把应连读的关系切断、短句是否无节奏堆叠、破折号/省略号是否滥用、引号内外是否造成朗读卡顿。标点以朗读和人物呼吸为准，不为追求“像人”故意制造病句；有意的拟声、口吃和停顿应保留。

### 8.6 句级输出合同

默认对每一处明确病灶输出：

```text
- 原句：〔原句〕
- 问题：〔具体问题类型和原因〕
- 修改：〔修改后的句子〕
```

同一段有多个独立问题时分开列；没有明显问题的句子跳过。全部列完后，若用户要求“完整修改后文本”，再给保留原有段落和章节划分的完整回稿。若用户只要过滤/标注，则只给“原句 + 问题”，不擅自给改写稿。若用户只要求整篇可直接使用的版本，可以隐藏逐条清单，但仍须在内部完成逐条保真回读。

句级修改原则：保持原意、主体、时序、条件、否定和设定；对白优先口语化但不强行加语气词；叙述优先短而具体；动作描写不替场面做总结；对话标签可补全但不得猜造新人物。修改后再检查每句是否仍与前后句衔接。

## 9. 代表性反例索引

以下句子不是固定禁词，而是诊断样本。遇到同类变体，按模式处理：

| 反例 | 病灶 | 改写方向 |
| --- | --- | --- |
| “荒原静得发冷。别人先找枪，我先找路。” | 通用末日开场、口号化对比 | 绑定正在发生的危险和修路的现实目的 |
| “她是电力节点长出来的人。” | 自造身份、因果断裂 | 写来处、故障、判断、动作 |
| “她被城里的电叫来。” | 把职责写成拟人召唤 | 写她听见什么、从哪里赶来、要解决什么 |
| “由地热抽水泵过滤出来的热咖啡。” | 动作主体错误、技术名词拼贴 | 让泵供暖/供水，让人物实际冲咖啡 |
| “这哪是在玩基建，分明是在修城顺带收人。” | 作者旁白、后宫标签化 | 用人物的具体决定和关系变化表达 |
| “魔物排队送死，系统转化金币。” | 结果跳跃、无压力战斗 | 写寻路限制、主角操作、设施损耗和回收结果 |
